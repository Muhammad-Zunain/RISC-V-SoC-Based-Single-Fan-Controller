## CPU review

The decoder covers the RV32I base opcode classes used for LUI/AUIPC, JAL/JALR, all six conditional branches, five base loads, three stores, OP-IMM, OP, FENCE and ECALL/EBREAK. Illegal funct3/funct7 combinations are blocked from state-changing controls.

The register file protects x0 from writes and returns zero for reads of x0. JAL/JALR link writeback is `pc+4`. JALR clears target bit 0. Taken branch/jump target alignment is checked for the base 4-byte instruction alignment. Load/store byte-lane logic is little-endian and supports LB/LBU/LH/LHU/LW and SB/SH/SW; this implementation deliberately traps naturally misaligned halfword/word accesses.

The core is architecturally multicycle because of explicit registered FSM boundaries; this does not by itself require an SDC multicycle-path exception. The existing trap-priority writeback guard `if (!halted_o && !trap_request)` is retained.

## Memory and bus review

The IMEM wrapper rejects non-word-aligned instruction fetches and out-of-range addresses. DMEM and CONFIG wrappers perform base/range checks while the LSU owns subword alignment and byte-strobe generation. Each wrapper returns a registered one-cycle acknowledgement through `pending_q`.

The SoC latches the selected target for an outstanding transaction and holds it until acknowledgement. MMIO peripheral read data is captured at request acceptance. The CPU issues a request only in explicit `FETCH_REQ`/`MEM_REQ` states, preventing repeated writes while waiting for acknowledgement.

## Peripheral review

- PWM: programmable enable/period/duty; period zero forces low and duty >= period produces 100% while enabled.
- UART: 8N1 TX/RX; RX input has a two-flop synchronizer; sticky status/error handling is present.
- SPI: fixed 8-bit, MSB-first Mode 0. MISO is sampled on the rising edge and MOSI is updated for the next bit on the falling edge.

## Synthesis observability note

Genus is allowed to remove unobservable/unloaded logic. In the ASIC top, PWM, UART TX, SPI signals, `status_halted_o`, and `status_trap_o` are primary outputs and therefore define observable behavior. `debug_pc`, `debug_instr`, `debug_trap_cause`, and `debug_state` were originally internal-only in the ASIC top, so logic used solely to drive those debug nets was legitimately optimized away. Do not globally preserve all hierarchy merely to keep the schematic visually identical to RTL.

**Update (2026-09-14):** `debug_pc_o`, `debug_instr_o`, `debug_trap_cause_o`, and `debug_state_o` are now real top-level output ports on `riscv_fan_soc_asic_top` (see README section 38) so the full CPU debug bus stays reachable and is no longer dropped by Genus's boundary optimization. This is a deliberate pinout change for bring-up/debug visibility, not a reversal of the observability principle above: any signal that still has no path to a kept output or port will still be, correctly, optimized away.

## Custom macro integration contract

The CPU/SoC should remain 32-bit. The custom memory adapter must preserve the logical 256 x 32 interface and one-cycle read contract. DMEM and CONFIG need four byte write enables if `SB`, `SH`, and `SW` are to remain single transactions.

If the physical macro is 256 x 16, use two macros in parallel per logical memory (six physical macros total for IMEM/DMEM/CONFIG). If it is 128 x 16, width and depth banking require four per logical memory (twelve total). A macro with no byte write mask cannot directly preserve `SB` on DMEM/CONFIG without read-modify-write, which would require a bus/latency redesign.

A fabricated SRAM does not power up with `$readmemh` contents. IMEM therefore ultimately needs either a ROM-like macro or a real SRAM boot/preload mechanism.

For physical implementation, the custom macro must be characterized for the same PDK/process and compatible voltage/corners as the standard-cell flow and should provide the required logical/timing/physical views (at minimum a functional/logical model, Liberty timing/power, LEF abstract, and GDS; CDL/SPICE when used for LVS/signoff).
